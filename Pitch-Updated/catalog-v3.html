Unit & Integration TestingTesting

Run the Test Generation Agent against your implementation to generate a full suite with happy path, edge cases, null inputs, and exception scenarios. Review every generated test — especially mock setups. All tests must pass on CI before proceeding.

🤖 Test Generation Agent 💬 EF Core Query Analyser
Copilot Chat
@test-gen Generate full xUnit test suite for UserService.
Include: happy path, null inputs, not-found, DB exceptions.
Use Moq. CancellationToken in all async tests.

// Then verify locally
dotnet test --filter Category=Unit
⚠️

Never commit untested AI-generated tests. Generated tests can compile and run but test the wrong behaviour. Read the assertion logic — it must genuinely exercise your code.

Security ReviewSecurity

Run both security agents on any PR touching auth, data access, API endpoints, or configuration. Premium model only — free models lack the depth for reliable security analysis and can produce false confidence.

🤖 Security Agent (Checkmarx) 🤖 SonarQube Agent 💬 Auth Flow Reviewer
Copilot Chat — Premium model REQUIRED
@security-cx Review this controller for injection vulnerabilities,
missing auth checks, and insecure deserialization.

@sonar Fix the cognitive complexity and null reference
warnings flagged in UserService.ProcessRequest()
⚠️

Premium model is mandatory for all security agents. A missed vulnerability costs far more than the extra token usage.

Automated AI PR Review PipelineAutomated

When a PR is created or pushed to in Azure DevOps, the AI review pipeline runs automatically as a branch policy. It posts inline comments on the diff and sets the build to pass (warnings only) or fail (errors found). Here are the exact rules it enforces:

🤖

The AI pipeline is a build policy step in ADO. Re-trigger by pushing a new commit. Fix Error items before peer reviewers are asked to approve.

03 — Guidelines

Dos & Don'ts.

✓ Best Practices
  • ✓
    Review every suggestion — you own what ships.
  • ✓
    Give context — framework, pattern, constraints in every prompt.
  • ✓
    Use specialist agents — don't use general chat when an agent exists for it.
  • ✓
    Premium for critical paths — auth, payments, data pipelines.
  • ✓
    Run AI review before peer review — let the pipeline handle style.
  • ✓
    Iterate: interface → impl → tests → review.
✕ Anti-Patterns
  • ✕
    Never paste secrets or PII — zero tolerance, use Key Vault.
  • ✕
    Don't accept without understanding — can't explain it? don't commit it.
  • ✕
    Free model for security — always premium + specialist agent.
  • ✕
    Vague prompts — "write a service" gives generic output.
  • ✕
    Generate entire features in one shot — bugs compound.
  • ✕
    Share proprietary algorithms verbatim — rephrase generically.
04 — Prompting

Talk to Copilot like a senior dev.

01
Name the pattern and framework

Always state which pattern and version. Context eliminates ambiguity.

// ❌ Write a user service
// ✓ IUserRepository.GetAsync() EF Core async,
//   Repository pattern, returns UserDto not entity,
//   CancellationToken required, AsNoTracking
02
Use slash commands

Built-in commands are optimised for specific intents — use before free-text.

/fix      Fix this code
/explain  Explain this code
/tests    Generate tests
/doc      Generate docs
03
Scope with #file and #selection

Reference the exact file so Copilot doesn't guess scope.

#file:UserService.cs
Refactor email logic into
IEmailNotificationService.
04
Ask it to explain its own output

Before accepting, ask Copilot to walk through the generated code.

"Walk through this line by line.
What could go wrong? What edge
cases does it miss?"
