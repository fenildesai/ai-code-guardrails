The Developer Struggle

The Evolution of AI Strategy

Phase 1: Prompt Engineering

Focuses on "Clever Phrasing". It relies on the developer's ability to ask the right way every single time. (Fragile & Unscalable)

Phase 2: Context Engineering

Focuses on "Right Information". Bringing the data, standards, and rules to the AI in the right format automatically. (Durable & Trusted)

"Context engineering is focused less on clever phrasing and more on bringing the right information (in the right format) to the LLM."

How to Get Started

We have created a Base Framework with production-ready examples for all 4 pillars. Teams can adopt this immediately and customize it based on project DNA. 

# .github/copilot-instructions.md
# Project: Core Services

## Coding Standards
* Use C# 11+ features (primary constructors, file-scoped namespaces).
* Follow DRY and SOLID principles.
* Use NSubstitute for all mocking.

## Security
* Never hardcode secrets. Use Azure KeyVault integration.
* All external inputs must be validated using FluentValidation.

# .github/prompts/fix-sonar.prompts.md
# Goal: Automate Technical Debt liquidation

Review the active file for any SonarQube "Code Smells" or "Critical Issues".
For each issue found:
1. Explain the violation.
2. Provide a refactored version of the code that resolves the issue while 
   maintaining the same external behavior.
3. Follow our internal architectural guidelines (Private Properties only).
